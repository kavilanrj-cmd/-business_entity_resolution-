# Business Entity Resolution

A classical-ML, fully local pipeline for matching **Source 1** reference business
entities against the noisier **Source 2** and **Source 3** business records.

Each Source 1 entity is resolved to **zero, one, or many** Source 2/3 records. The
system is retrieval + classification: blocking narrows the search space, a
gradient-boosted classifier scores the surviving candidate pairs, and a single
tuned threshold turns scores into matches.

No external data sources, geocoding services, or LLM APIs are used.

---

## Metric

Scoring is **macro-averaged F0.5 over Source 1 entities**, not over pairs.

```
F0.5 = 1.25 * precision * recall / (0.25 * precision + recall)
```

Because F0.5 weights precision twice as heavily as recall, and because a Source 1
entity with no true matches that receives a prediction scores **0.0** (the
*singleton violation*), false positives are punished hard. Roughly 35% of the
training entities are true singletons, so precision is where the score is won or
lost.

Threshold selection therefore breaks ties toward **higher macro precision**, then
toward the **higher** threshold.

## Data

> **The `dataset/` shipped in this repo is synthetic.** It is generated by
> `tests/make_fixture.py` so the pipeline, metric, and blocking code can run and be
> unit-tested without the real files present. It is *not* the Amazon challenge data.
> Drop the real `dataset/` directory in its place to run against actual data; no
> code changes are required.

Layout:

```
dataset/
  train/
    train_source1.tsv        # clean reference entities
    train_source2.tsv        # noisy variant A
    train_source3.tsv        # noisy variant B
    train_ground_truth.tsv   # labels for training only
  test/
    test_source1.tsv
    test_source2.tsv
    test_source3.tsv
```

### Record format

Tab-separated, four columns, all read as strings (blank cells become null):

| Column | Aliases accepted |
| --- | --- |
| `entity_id` | `id`, `entityid`, `businessid`, `business_id` |
| `business_name` | `name`, `businessname`, `company_name`, `companyname` |
| `business_address` | `address`, `businessaddress`, `addr` |
| `country` | `country_code`, `countrycode`, `nation` |

```tsv
entity_id	business_name	business_address	country
S1-00001	Green Electronics & Sons	2328 Market Road, Miami, FL, 33101	us
S2-00001	STAR IMPORTS INC	1921 Gandhi Road, WA	us
S3-00001		10/99 , Towyer A , Near Bus Stand , Bengaluru , Karnataka , 560001	in
```

`business_address` and `country` may be absent or empty; only `entity_id` and
`business_name` are strictly required.

### Ground-truth format

One row per Source 1 entity, **including entities with no match** (empty cell):

```tsv
source1_id	matched_entity_ids
S1-00001	
S1-00002	S3-00001
```

Multiple matches are comma-separated. Long-format ground truth (one true pair per
row, with an optional `is_match` label column) is also accepted.

### Output format

`output/matching_results.tsv` — one row per test Source 1 entity, always, with an
empty cell for unmatched entities:

```tsv
source1_entity_id	matched_entity_ids
T1-00001	S2-00001,S3-00042
T1-00002	
```

Inference validates the submission before returning and raises rather than leaving
a malformed file behind.

## Usage

Run everything from the project root.

### Explore the data

```bash
python -m scripts.explore_dataset
python -m scripts.explore_dataset --train-dir dataset/train --test-dir dataset/test
```

Prints per-table shape/columns/dtypes/nulls, normalization spot-checks,
ground-truth cardinality histogram, duplicate statistics, country distributions
(including an open-set train/test check), and a train/test ID-overlap leakage check.

### Check blocking quality

```bash
python -m scripts.check_blocking --train-dir dataset/train
```

Reports candidate-generation statistics, overall and per-strategy candidate
recall, blocking-failure examples, and feature-matrix shape, class balance, and
constant features. Candidate recall is the hard ceiling on achievable F0.5, so
this is the first thing to check.

### Train

```bash
python -m scripts.train
python -m scripts.train --skip-validation          # fast, threshold is not data-driven
python -m scripts.train --limit-source1 300        # quick smoke run
python -m scripts.train --config config.yaml
```

| Flag | Default | Purpose |
| --- | --- | --- |
| `--config` | `None` | optional YAML configuration file |
| `--base-dir` | CWD | project root |
| `--train-dir` | `dataset/train` | override training data directory |
| `--models-dir` | `models` | where to write the model bundle |
| `--reports-dir` | `reports` | where to write reports |
| `--models` | all three | candidates to compare, e.g. `logistic_regression random_forest` |
| `--n-splits` | `4` | cross-validation folds |
| `--limit-source1` | `None` | only use the first N Source 1 entities |
| `--skip-validation` | `False` | skip CV (threshold will not be data-driven) |
| `--no-save` | `False` | do not write the model or reports |
| `--log-level` | `INFO` | `DEBUG` / `INFO` / `WARNING` |

### Infer

```bash
python -m scripts.infer
python -m scripts.infer --limit-source1 100     # quick smoke run
python -m scripts.infer --no-validate
```

| Flag | Default | Purpose |
| --- | --- | --- |
| `--config` | `None` | optional YAML configuration file |
| `--base-dir` | CWD | project root |
| `--test-dir` | `dataset/test` | override test data directory |
| `--models-dir` | `models` | where the trained bundle lives |
| `--output-dir` | `output` | where to write the submission |
| `--limit-source1` | `None` | only score the first N test Source 1 entities |

> `python scripts/train.py` / `python scripts/infer.py`, but
> `scripts.explore_dataset` and `scripts.check_blocking` must be invoked as modules
> (`python -m ...`) from the project root.

## Architecture

Three shared stages, reused by both training and inference. The only difference is
where the labels come from — training reads the ground-truth file, inference has no
labels at all.

```
preprocess  ->  retrieve  ->  score
```

1. **preprocess** — normalize names, addresses, and countries. Adds
   `business_name_normalized`, `business_name_core`, `business_address_normalized`,
   `business_address_core`, `country_normalized`, and extracted `pincode`,
   `house_number`, `city`, `state`. Original columns are preserved.
2. **retrieve** — build the candidate set: the Source 1 → (Source 2 ∪ Source 3)
   union produced by the blocking strategies below.
3. **score** — featurize the candidates and apply the learned model. Training
   passes `model=None` and scores are all zero; a hard check rejects any feature
   matrix containing NaN or infinite values.

### Training pipeline

`src/pipeline/train_pipeline.py`:

1. Load `dataset/train` + the ground truth.
2. Preprocess and retrieve candidates for every training Source 1 entity.
3. Measure **candidate recall** — the hard ceiling on achievable F0.5.
4. Cross-validate the candidate models and pick one on out-of-fold F0.5.
5. Refit the winner on all candidate pairs.
6. Attribute the remaining errors to blocking vs. the model.
7. Persist the model, the chosen threshold, and the reports.

The selected threshold comes from out-of-fold predictions only, so the number in
the report is not a training-set fit.

### Inference pipeline

`src/pipeline/inference_pipeline.py`: load the bundle → load test data → retrieve →
score (with a feature-layout guard against the trained schema) → apply the
threshold → write `matching_results.tsv` and `candidate_pairs.tsv` → validate.

### Cross-validation and leakage

CV folds are split on **Source 1 entities**, not on candidate pairs, so pairs from
the same entity cannot straddle a fold. The retrieval pool and the TF-IDF/IDF
statistics are deliberately shared across folds because they are label-free.

## Blocking

Candidate generation is a union of five strategies, deduplicated by composite
`(query, pool)` key while keeping the max score and OR-ing the strategy mask.

| Strategy | Approach |
| --- | --- |
| `exact_name` | dictionary lookup on the normalized and core name |
| `token_name` | IDF-weighted name-token cosine top-K (min score 0.30, max 150/entity) |
| `tfidf_name` | character n-gram TF-IDF cosine top-K, for noisy names (`char_wb`, 2–5 grams, K=40, min 0.20) |
| `address_token` | IDF-weighted address-token cosine top-K, with a generic-token stop-list (min 0.35, max 100/entity) |
| `country_aware` | character n-gram TF-IDF top-K restricted to the same-country pool, plus a global fallback for Source 1 rows with a missing/unknown country (K=15, min 0.25) |

Post-union caps: `max_candidates_per_s1 = 400`, `min_candidates_per_s1 = 5`.

Countries are treated as an **open set** — there is no hard-coded whitelist
anywhere, and the country groups used in retrieval are derived from the observed
data. The test split intentionally contains countries absent from train.

## Model

Three candidates are cross-validated and the winner is chosen on out-of-fold F0.5
(never accuracy):

| Name | Configuration |
| --- | --- |
| `logistic_regression` | `StandardScaler` + `LogisticRegression`, `max_iter=2000`, `class_weight="balanced"`, `lbfgs` |
| `random_forest` | 400 trees, `min_samples_leaf=2`, `max_features=0.5`, `class_weight="balanced_subsample"` |
| `hist_gradient_boosting` | 400 iterations, `learning_rate=0.06`, 31 leaves, `min_samples_leaf=20`, `l2_regularization=1.0`, `class_weight="balanced"`, early stopping |

`random_state=42` throughout.

**Class imbalance.** The positive class is typically well under 1% of candidate
pairs. The mitigations are `class_weight="balanced"` and keeping *all* generated
candidates — no negative sub-sampling — so a verified positive pair is never
relabelled as negative.

**Decision rule.** A single flat threshold on `predict_proba`
(`keep = scores >= threshold`). An entity may get 0, 1, or many matches; there is no
per-entity top-1 constraint. Per-strategy threshold overrides are tested and kept
only if they beat the flat rule on validation.

**Threshold search.** Two families are evaluated: a coarse grid (0.01–0.99) and the
exact observed score breakpoints (capped at 400). Predictions only change when the
threshold crosses an observed score, so the breakpoint set is complete — no
threshold can be missed by a coarse grid.

## Features

~62 columns, no hand-tuned weights. Missingness is represented explicitly, so the
matrix never contains NaN.

- **Name** (22) — exact/core/raw match, common-prefix ratio, Jaccard, token overlap
  and containment, Levenshtein, Jaro-Winkler, token-sort and token-set ratios,
  TF-IDF cosine, character n-gram Jaccard, length difference and ratio,
  first/last token match, numeric match, both-missing.
- **Address** (27) — the same idea over the normalized address, plus explicit
  `pincode`, `house_number`, `city`, and `state` match / both-present / conflict
  triples.
- **Country** (5) — exact match, conflict, missing, query-missing, candidate-missing.
- **Combined** (8, on by default) — geometric / arithmetic / min / max name+address
  score, the gap between them, and exact-name-with-conflict guards.

## Tests

```bash
python -m pytest tests/ -v
```

Use `python -m pytest` from the project root so the project root lands on
`sys.path` (`tests/test_metrics.py` imports `from src.evaluation.metrics import ...`
and there is no `conftest.py`).

The suite covers the F0.5 implementation: hand-computed per-entity cases,
macro-averaging, missing prediction keys treated as empty, agreement between the
threshold sweep and direct evaluation, singleton-violation counting, the
precision optimum, and a set of regression tests for tied scores — including one
that reproduces a real bug where the breakpoint sweep reported F0.5 = 0.87 when the
true value was 0.27.

`tests/make_fixture.py` is not collected by pytest. It is a CLI generator for the
synthetic dataset:

```bash
python -m tests.make_fixture --out dataset
python -m tests.make_fixture --out dataset --train-s1 300 --train-pool 500 \
    --test-s1 100 --test-pool 200 --seed 42
```

  config.py       all configuration dataclasses, YAML/JSON loading, dotted overrides

## Configuration

`src/config.py` holds dataclasses for paths, blocking, features, model, threshold,
output, and logging. Any field can be overridden from a YAML file via
`--config`, using dotted keys:

```yaml
paths:
  base_dir: .
  train_dir: dataset/train
model:
  candidates: [hist_gradient_boosting]
  n_splits: 5
```

Supported dotted keys: `paths.base_dir`, `paths.train_dir`, `paths.models_dir`,
`paths.reports_dir`, `model.candidates`, `model.n_splits`, `log_level`
(train); `paths.base_dir`, `paths.test_dir`, `paths.models_dir`,
`paths.output_dir`, `log_level` (infer).
